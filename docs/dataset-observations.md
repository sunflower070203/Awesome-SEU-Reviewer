### 关键发现 1：文本层不可信

前两份 PDF 看似"电子版有文本层"，但 `get_text_range()` 提取出来是**字形索引乱码**：

```
驴 H 氓 脝   拢 脷 拢A 脷搂
1. e脺脟 x 鈭� 1 = y 鈭� 1
```

第三份则完全没有文本层。

**结论：三份都必须走图像路径**——先渲染成图片，再识别。这比"先试文本层、失败再 OCR"更可靠，也简化了实现（统一入口）。

### 关键发现 2：渲染成图片后识别质量极高

用 `pypdfium2` 以 2 倍缩放渲染成 PNG（1191×1684），**公式、下标、分式、矩阵全部可准确还原**：

- `$\iint_D |y-\sqrt{x}|\,d\sigma$`
- `$\sum_{n=1}^{\infty} a_n (x-1)^n$`
- `$S(-\frac{1}{2})$`

> 这条路线的含义：**Skill A 的第一优先级不必是"接第三方 OCR API"，而是"高质量渲染 + 视觉模型识别"**。免费、准确、且对公式天然友好。

## 三、对算法设计的 5 条启示

### 1. 抛弃「重统计」路线

3 份文档时 TF-IDF 的 IDF 项为 `log(3/df)`，取值只有 3 档（0 / 0.4 / 1.1），**区分度极低**。共现矩阵同样稀疏到无意义。

**结论：不要依赖需要"文档数"的统计方法。**

### 2. 主力应是「题目级相似度聚类」

既然重复率这么高，核心问题变成：

> 把 3 份卷子的题**按相似度分组**，统计每组的跨卷出现次数。

- 一组在 3 份卷都出现 → **必考**
- 出现 2/3 → 高度可能
- 出现 1/3 但有 PPT 佐证 → 可能

这不需要统计学，只需要**语义相似度**（sentence-transformers 或直接让 LLM 判定）。

### 3. 「位置-考点映射」是强特征

观察到的规律：
- **第 4 题**：连续两年考「绝对值函数的二重积分」
- **第 9 题**：连续两年考「Fourier 级数和函数求值」
- **第 1 题**：连续两年考「空间中直线/平面关系」

**题号位置本身携带信息。** 算法应把 `(题型, 题号)` 作为聚类的辅助键。

### 4. 权重公式（替代 TF-IDF）

**前提**：经用户确认，本课程**没有课件 PPT**，且三份试卷属于**同一门课**（「高等数学分析 II」与「工科数学分析 II」是同一门课的两个名目），可合并进同一预测池。

因此权重只用两个维度：

```
score = 0.75 × 跨卷重复度 + 0.25 × 位置稳定性

跨卷重复度 = 该题簇出现的卷数 / 总卷数
  3/3 → 1.00   2/3 → 0.67   1/3 → 0.33

位置稳定性 = 该簇内「题型 + 题号」一致的样本占比
  例：某簇 3 题分别在(填空,4)(填空,4)(计算,2) → 2/3 一致 → 0.67
```

> 原始设计含「PPT 覆盖度」一项。既然本课程无 PPT，该项移除。
> 若未来用户提供课件，可作为可选维度重新引入（届时权重需重新分配）。

### 5. 小样本下，「可解释」比「精确」更重要

3 份卷子的统计不可能给出精确概率。所以输出重点应是：

- **依据链**：「第 4 题连续 2 年考绝对值积分」
- **不确定标注**：「仅 1/3 出现，低置信」
- **交叉验证**：同一考点在不同题型中的出现情况

这正是 Knowledge Tracing 类黑盒模型做不到的。

## 四、对 Skill A（OCR）的优先级调整

原设计把 OCR 当作"手写/拍照场景"的补救手段。基于本次观察，建议**上调其地位**：

| 原优先级 | 新优先级 | 理由 |
|---|---|---|
| 接腾讯云手写 OCR API | **先做：PDF/图片 → 高清渲染 → 视觉模型识别** | 3 份真实数据中 2 份文本层乱码、1 份无文本层；渲染+视觉是唯一可靠路径，且免费、公式友好 |
| 手写 OCR | 保留（针对回忆版手写稿） | 真实场景仍有手写源 |
| Mathpix | 降为可选（公式兜底） | 视觉模型已能准确还原公式 |

**统一入口**：无论输入是"电子 PDF"还是"拍照"，一律先渲染/预处理成图片，再识别。避免"先试文本层"的分支逻辑。

## 六、下一步

实现 Skill B（`scripts/predict/`）：
