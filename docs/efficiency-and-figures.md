# 效率与图形：两个痛点的诊断与候选方案

> 2026-10-12，针对「额度消耗偏高」与「电路图效果一般」两件事做的实测诊断。

---

## 一、额度消耗：钱花在哪了

拿刚做完的模电试卷实测（8 张 PPT 投影照片）：

| 项目 | OpenAI 算法 | Claude 算法 |
|---|---|---|
| 8 张原图（2649 ~ 4032 px） | 6 120 | **85 559** |
| 文字（题目 JSON + .tex + 绘图脚本） | 14 183 | 14 183 |

**结论一：图片是绝对大头，且和分辨率呈平方关系。**

单张 `2022 (5).png` 是 4032×3024，按 Claude 的算法就是 **16 258 token** —— 一张图顶得上一篇长文。

**结论二：分辨率只要降一档，收益是数量级的。**

| 分辨率 | Claude 单张 | 8 张合计 |
|---|---|---|
| 4032×3024（原图） | 16 258 | ~85 559 |
| 1600×1200 | 2 560 | ~13 000 |
| **1 万像素级（≈1400 长边）** | ~1 700 | **~10 000** |

PPT 投影片**字很大、信息密度低**，1600 px 长边完全够看清题干。

**结论三：还有一笔隐性开销——调试时的反复看图。**

这次画电路图，我改一轮就渲染一次看效果，前后看了 6~7 次。
每次都是 1000+ token，合计约 6 000~8 000 —— 和"把 8 张原图读一遍"同量级。

## 二、候选方案 A：图片预处理

| 手段 | 省多少 | 代价 |
|---|---|---|
| **① 自动裁掉投影幕布外的区域** | 面积常可减半 → 同分辨率下更清晰 | 需做边缘检测 |
| **② 降长边到 1400~1600 px** | Claude **省 ~85%**；OpenAI 可能省 31% | 极小字的扫描件有风险 |
| **③ 透视校正**（把斜拍拉正） | 不省 token，但提升识别准确率 | 需要四角检测 |
| ④ 转灰度 / 压 JPEG | **不省**（按像素或分块计费，不看字节） | —— |

**建议组合：① + ②**。

- 对「拍屏幕/投影」的输入：裁内容区 → 降到 1400 px → 识别质量不降反升（因为去掉了干扰）
- 对「扫描试卷」（小字密排）：只做 ①，分辨率保持 2000 px 以上

**实现代价**：一个 `preprocess.py`（约 100 行，PIL + 简单阈值），一次性投入。

## 三、候选方案 B：电路图改用 circuitikz

当前用的是「手写 SVG 坐标 + svglib 转 PDF」。问题是：

- 元件符号自己画的，**不如标准符号规范**
- 用**绝对坐标**布局，全靠试，所以改了又改
- 生成的是**图片文件**，还要打进 zip 上传 Overleaf

`circuitikz` 是 LaTeX 生态里画电路的标准宏包，Overleaf 原生支持。

**同一个共射放大电路，两种写法对比：**

SVG（现在，节选）：
```python
s.append(line(210, 45, 210, 60))
s.append(resistor_v(210, 78, "$R_C$", side="right", half=16))
s.append(line(210, 96, 210, 120))
s.append(circle(210, 120, 2.6, fill=S))
```

circuitikz：
```latex
\draw (0,0) node[npn](T){$T$}
      (T.C) to[R=$R_C$] ++(0,2) node[vcc]{$V_{CC}$}
      (T.E) to[R=$R_E$] ++(0,-2) node[ground]{};
```

| 维度 | 手写 SVG（现在） | circuitikz |
|---|---|---|
| 元件符号 | 自绘，简化 | **标准符号，自动** |
| 布局方式 | 绝对坐标（试错） | **相对定位，`to[R=...]`** |
| 输出的东西 | SVG → PDF → 打包上传 | **直接写在 .tex 里** |
| 用户后续修改 | 得看懂 Python 脚本 | **改 .tex 即可** |
| 波形/时序图 | 手绘折线（正弦画成了三角波） | `\draw plot` 直接画函数曲线 |
| Overleaf 依赖 | 需上传图片文件夹 | 只需 `\usepackage{circuitikz}` |
| Agent 生成成本 | 脚本 9.6k token + 多轮看图 | **代码更短，一轮成型** |

**唯一要注意**：`exampaper.cls` 需要加 `\usepackage{circuitikz}`（几行改动），
且编译时间会略增（Overleaf 免费版仍在可接受范围）。

**波形图也一并解决**：现在的"正弦波"是折线近似（看着像三角波），
TikZ 里一行 `\draw plot (\x, {sin(\x r)});` 就是真正弦。

## 四、候选方案 C：减少调试轮次

| 做法 | 收益 |
|---|---|
| **元件库一次做对**（已验证：电阻/电容/二极管/三极管/接地） | 不用每次从头试 |
| **坐标网格对齐**（所有元件落在 20 px 网格上） | 少一半"看起来歪了"的返工 |
| **代码自检代替看图**（检查坐标是否越界、元素数是否齐全） | 用 0 token 的断言替代 1000 token 的截图 |
| **批量渲染、只抽查 1~2 张** | 看图次数从 6~7 降到 1~2 |

若采用 circuitikz，这一项基本自动解决（编译一次就知道对不对）。

## 五、对多 Agent 评测的意义

跑 `benchmark/TASK.md` 对比各 Agent 时，**必须固定图片预处理策略**，
否则 token 差异会被分辨率淹没 —— 同一份材料，压缩与否能差 8 倍。

建议在任务说明里写死：

```
所有输入图片统一降到长边 1600px 再交给 Agent
```

## 六、建议（待用户拍板）

| 优先级 | 措施 | 预期收益 | 工作量 |
|---|---|---|---|
| **P0** | 图片预处理（裁剪 + 降分辨率） | **Claude 类省 80%+** | 中（一个脚本） |
| **P1** | 电路图改用 circuitikz | 图形质量↑、上传步骤↓、代码↓ | 中（改 cls + 重画） |
| **P2** | 调试规范（批量渲染 + 代码自检） | 省 5k~8k/次 | 小（写进 SKILL.md） |
| P3 | 优先尝试文本层 | 电子版 PDF 完全免图 | 小（已在 render.py 报告字符数） |

**注意**：P0 和 P1 是**独立的两件事** —— 前者省 token，后者提图形质量，可以分别做。
