# Token 消耗优化

> 目标：在**不降低识别质量**的前提下，把单次任务的 token 消耗压到最低。
> 所有数字来自 `scripts/bench/estimate_tokens.py` 的实测。

## 一、成本结构：图片是绝对大头

### 实测：一页 A4 试卷扫描件在不同分辨率下的开销

| 渲染倍率 | 像素 | OpenAI 算法 | Claude 算法 |
|---|---|---|---|
| **2.0×**（当前默认） | 1191 × 1684 | **1105** token | **2675** token |
| 1.5× | 893 × 1263 | 1105 token | 1503 token |
| **1.0×** | 596 × 842 | **765** token | **670** token |

**关键发现**：

1. **两种算法的缩放规律完全不同**
   - OpenAI 按 **512×512 分块**计费 → 分辨率在"同一档"内变化**完全不省钱**（2.0× 和 1.5× 都是 1105）
   - Claude 按**面积**计费 → 降分辨率**线性省钱**
   - 只有跨过分块档位（如降到 1.0×）才能同时省两边的钱

2. **6 页试卷的总对比**

   | 配置 | OpenAI | Claude |
   |---|---|---|
   | 2.0× | 6630 | 16050 |
   | **1.0×** | **4590** | **4020** |
   | 节省 | **-31%** | **-75%** |

3. **文本几乎不花钱**
   一份 18 题的 `questions.json` ≈ 3475 token，对应的 `.tex` ≈ 2724 token。
   **全部文本加起来通常不到两张图的成本。**

> 结论：**优化 token = 优化图片**。文本侧没什么可省的，也不该省（题干丢掉就没法出题了）。

## 二、可用的优化手段（按性价比排序）

### ① 降渲染倍率 —— 收益最大，风险可控

```bash
python scripts/ocr/render.py --input exam.pdf --outdir .tmp-render --scale 1.0
```

**实测**：1.0× 渲染的试卷照片仍能准确识别题干、选项与波形图（已人工核对）。
**风险**：手拍/低质量扫描件在 1.0× 下细节可能丢失。

**建议**：

| 输入质量 | 建议倍率 |
|---|---|
| 电子版 PDF（矢量原生） | **1.0×**（够用） |
| 清晰扫描件 | 1.0–1.5× |
| 手机拍的屏幕/纸张 | 1.5–2.0× |

### ② 只渲染需要的页 —— 收益直接

试卷里常有：
- 答案页 / 解答页（整理题目时不需要）
- 空白页、封面页
- 与目标题型无关的部分

**做法**：`render.py` 支持单文件输入，可先用 `--scale 0.5` 渲染全部页做"缩略图预览"，确定页码后再对目标页用高倍率渲染。

```bash
# 第一步：低倍率扫一遍，定位页码
python scripts/ocr/render.py --input exam.pdf --outdir .tmp-thumbs --scale 0.5

# 第二步：只渲染需要的页（用 pdftoppm 或自行裁剪后的单页 PDF）
python scripts/ocr/render.py --input page3.pdf --outdir .tmp-render --scale 1.5
```

### ③ 分批处理，不要一次贴所有页

**反例**：一次把 17 页 PNG 全读进上下文 → 峰值上下文暴涨。

**正例**：每次读 2–3 页，提取完就写入 JSON，**后续不再重复读图**。

**关键**：`questions.json` 一旦生成，后续所有步骤（聚类、归并、排版）都只吃 JSON，**不再碰图片**。

### ④ 考点归并时只喂摘要

`references/topic-merge.md` 里已写明：归并**不需要题干全文**，只要「题号 + 一句话摘要」即可。
把 36 道题的完整 LaTeX（≈7000 token）压成题号 + 摘要（≈500 token），**省 90%**。

### ⑤ 图片格式：PNG 还是 JPEG？

- **PNG**：无损，文件大，但**对 token 无影响**（计费按像素/分块，不按字节）
- **JPEG**：文件小，传输快，但**不省 token**

**结论**：不必为了 token 换格式。选 PNG（无损，识别更稳）。
只有在**上传带宽受限**时才考虑 JPEG。

## 三、反模式（看起来省、其实不省）

| 做法 | 为什么不省 |
|---|---|
| 把 PNG 压成高质量 JPEG | token 按像素算，文件变小无用 |
| 2.0× → 1.5×（对 OpenAI 算法） | 仍落在同一分块档（2×3 块），token 不变 |
| 降低图片"质量"但保持分辨率 | 同上 |
| 把题干裁得很短 | 文本本来就便宜，裁掉反而丢信息 |

## 四、推荐配置

```bash
# 电子版 PDF（最常见）
python scripts/ocr/render.py --input exam.pdf --outdir .tmp-render --scale 1.0

# 手拍件
python scripts/ocr/render.py --input photos/ --outdir .tmp-render --scale 1.5
```

预期单份试卷（6 页）的**图片成本**：

- 电子版（1.0×）：OpenAI ≈ 4590 / Claude ≈ 4020
- 手拍件（1.5×）：OpenAI ≈ 6630 / Claude ≈ 9000

再算上系统提示、技能文档（`SKILL.md` ≈ 4k token）与工具返回，**一次完整任务的量级在 15k–40k token**，具体取决于 Agent 每轮是否重读技能文档。

## 五、对多 Agent 对比的意义

跑 `benchmark/TASK.md` 时，务必记录：

1. **渲染倍率**（不一致就没法比）
2. **是否重复读图**（有的 Agent 会反复读同一页）
3. **峰值上下文**（一次贴 15 页的 Agent 峰值会明显更高）

这三项往往比"总 token"更能解释差异来源。
