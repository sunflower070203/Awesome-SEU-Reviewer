# 中文手写 OCR 特殊性

> OCR provider 在处理中文手写场景时的常见问题与缓解策略。

## 主要难点

### 1. 连笔字

**症状**：相邻字符笔画粘连，通用 OCR 切分失败  
**示例**："概率"被识别为"概" + 单字  
**缓解**：
- 启用腾讯云手写体识别（专门针对连笔训练）
- 增大图像分辨率（至少 300 DPI）
- LLM Vision 通道作为兜底

### 2. 涂抹

**症状**：原字符被横线/涂改液覆盖，原字符部分残缺  
**示例**：选择题答案被涂改  
**缓解**：
- 多通道投票（腾讯云 + PaddleOCR + LLM Vision）
- `needs_review=true` 标记，提示学生人工核对
- 在 `warnings` 字段列出"第 X 题存在涂抹，识别置信度低"

### 3. 公式与文字混合

**症状**：行内公式 `$x^2$` 紧跟中文，OCR 难以分离  
**示例**："求 $x^2$ 的值"被识别为"求 x2 的值"  
**缓解**：
- 用版面分析（layout detection）分离公式区域与文字区域
- 公式区域走 Mathpix，文字区域走手写 OCR
- 输出 LaTeX 时确保 `$...$` 包围完整公式

### 4. 行内特殊符号

**症状**：希腊字母、上下标被误识别  
**示例**：`μ` 被识别为 `u`，`σ²` 被识别为 `o2`  
**缓解**：
- 预处理时把可能的希腊字母（μ, σ, α, β 等）单独检测
- 后处理做常见替换（"u" → "\mu" 在数学上下文中）
- LLM Vision 通道语义纠正

### 5. 多页试卷页眉页脚

**症状**：OCR 把页码"3"、"共 4 页第 3 页"误识别为题目  
**缓解**：
- 版面分析识别页眉页脚区域
- 过滤短文本（< 5 字符）
- 学生可在 Skill 输出后删除

## 推荐 OCR Pipeline（手写场景）

```
原图
  ↓
[预处理] 自适应二值化 + 超分 + 去噪
  ↓
[版面分析] layout detection（公式/文字/图分离）
  ↓
[通道 A] 腾讯云手写体 → 结果 R1
[通道 B] PaddleOCR 手写 → 结果 R2
[通道 C] LLM Vision → 结果 R3
  ↓
[投票器] 编辑距离相似度匹配 + 置信度加权
  ↓
共识结果
  ↓
[后处理] needs_review 标记 + warnings 生成
```

## 置信度阈值建议

| 场景 | 阈值 | 行为 |
|---|---|---|
| 选择题 | < 0.7 | needs_review=true |
| 计算题 | < 0.85 | needs_review=true |
| 公式识别 | < 0.95 | needs_review=true（公式必须精确） |
| 填空题 | < 0.6 | needs_review=true |

## 学生人工校对清单

收到 Skill A 输出后，建议学生：

1. 检查所有 `needs_review=true` 的题目
2. 对比 `source_image` 字段打开原图核对
3. 检查所有公式的 LaTeX 是否正确
4. 检查选择题选项是否完整（A/B/C/D）
5. 检查填空题空位数是否正确

## 已知不支持场景

- 严重涂抹 + 涂抹超过 50% 字符面积：直接走"人工转录"模式
- 多列排版的试卷：版面分析可能错列，需要学生确认列序
- 试卷背面印有答案：当前 Skill 不区分正反面
